# DXEL - 회의록 자동화 시스템

## 1. 설치 및 실행 방법
 
### 1.1 요구 사양
 
| 항목 | 최소 사양 | 비고 |
|---|---|---|
| OS | Windows 10/11, macOS (Apple Silicon 포함) | 개발 및 테스트는 Windows(i7-1165G7, RAM 16GB), macOS(M4) 환경에서 진행 |
| CPU | 4코어 이상 권장 | GPU 없이 CPU만으로 동작. 코어 수가 많을수록 처리 속도 향상 |
| RAM | 16GB 이상 권장 | Whisper Large-v2 + Qwen3-4B 동시 로드 시 여유 필요 |
| 저장 공간 | 모델 파일 포함 약 6GB 이상 | Whisper Large-v2(약 3GB) + Qwen3-4B GGUF(약 2.5GB) |
| 필수 소프트웨어 | Python 3.10+, Node.js, ffmpeg | ffmpeg는 시스템 PATH에 등록되어 있어야 함 |
| 처리 속도 참고 | 음성 길이 대비 약 1.5~2배 시간 소요 | 예: 5분 분량 녹음 → 전사 약 8~13분 (테스트 환경 기준, 하드웨어에 따라 편차 있음) |
 
### 1.2 AI 모델 다운로드
 
용량 문제로 저장소에 모델 파일이 포함되어 있지 않습니다. 아래 경로에서 직접 받아 지정된 폴더에 넣어야 합니다.
 
**Faster-Whisper Large-v2**
```
https://huggingface.co/Systran/faster-whisper-large-v2
```
→ `models/faster-whisper-large-v2/` 폴더에 저장 (config.json, model.bin, tokenizer.json, vocabulary.txt 등)
 
**Qwen3-4B-Instruct-2507 GGUF (Q4_K_XL)**
```
https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF
```
→ `models/qwen3-4b/Qwen3-4B-Instruct-2507-UD-Q4_K_XL.gguf` 로 저장
 
### 1.3 백엔드 실행
 
```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
 
pip install fastapi uvicorn sqlalchemy python-multipart python-docx faster-whisper
pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
 
uvicorn main:app --reload
```
 
서버가 뜨면 `http://127.0.0.1:8000/docs` 에서 API 문서를 확인할 수 있습니다.
 
### 1.4 프론트엔드 실행
 
```bash
cd frontend/dxel_frontend
npm install
npm run dev
```
 
`http://localhost:5173` 에서 화면을 확인할 수 있습니다.

## 2. 모델 선정 근거
 
### 2.1 음성 전사 모델 — Faster-Whisper
 
세 가지 모델(Medium / Large-v2 / Large-v3)과 두 가지 연산 정밀도(int8 / float32)를 조합해 동일한 회의 녹음 샘플로 비교 실험을 진행했습니다.
 
| 조합 | 정확도 (체감) | 특이사항 |
|---|---|---|
| Medium + int8 | 양호 | 속도 빠름. 초기 기준값 |
| Medium + float32 | Medium+int8과 큰 차이 없음 | 정밀도 상향이 큰 효과 없음을 확인 |
| Large-v3 + int8 / float32 | Medium보다 낮음 | 환각(hallucination)성 오류 증가 경향 관찰 |
| **Large-v2 + float32 (최종 채택)** | **가장 우수** | 유사 발음 오인식은 있었으나 전체 맥락 보존이 가장 안정적 |
| Large-v2 + int8 | 채택 안 함 | 특정 구간이 무음으로 오판되어 내용이 누락되는 현상 확인 |
 
**선정 결론**: 모델 크기가 클수록 정확도가 비례해 좋아지는 것은 아니었으며, 본 프로젝트의 한국어 회의 녹음 데이터에서는 **Large-v3보다 Large-v2가 더 안정적인 결과**를 보였습니다. 또한 연산 정밀도는 int8보다 **float32가 발화 누락 없이 안정적**이어서 최종적으로 **Large-v2 + float32** 조합을 채택했습니다. 처리 속도보다 누락 없는 전사 완결성을 우선한 결정입니다.
 
추가로 `initial_prompt`를 통해 도메인 힌트(회의 녹음이라는 맥락, 반복되는 고유명사)를 제공하는 방식을 시도했으며, 일반적인 지시("정확하게 전사해주세요")보다 **구체적인 용어를 나열하는 방식이 더 유의미한 개선**을 보였습니다.
 
### 2.2 텍스트 생성 모델 — Qwen3-4B-Instruct-2507
 
| 항목 | 검토 내용 |
|---|---|
| 모델 크기 | 4B 파라미터. 로컬 환경(노트북급 CPU)에서 실행 가능한 크기를 우선 고려 |
| 양자화 | UD-Q4_K_XL(Unsloth Dynamic 4bit) 채택. 동일 비트수의 일반 양자화 대비 품질 저하가 적음 |
| 컨텍스트 길이 | 초기 8192로 설정했으나, 긴 회의(1시간 이상)에서 컨텍스트 초과 오류가 발생해 32768로 확장 |
| 대안 검토 | 8B 이상 모델도 존재하나, 로컬 실행 환경의 메모리 제약과 처리 속도를 고려해 4B를 유지 |

## 3. 오류 유형 정리표
 
개발 및 테스트 과정에서 실제로 발생했던 오류 유형을 정리했습니다.
 
| 오류 유형 | 증상 | 원인 | 대응 |
|---|---|---|---|
| 유사 발음 오인식 | "위치" → "유치" | 발음이 유사한 단어를 잘못 인식 | `initial_prompt`에 자주 등장하는 용어를 명시해 개선 시도 |
| 문맥 오인식 | "전년 12월" → "참여 시간이죠" / "이 청년시절이죠" | 배경 잡음, 발화 속도 등으로 해당 구간의 음성 명료도가 낮음 | 모델/정밀도 변경으로도 근본 해결 안 됨. 사용자 직접 교정 필요 구간으로 분류 |
| 구간 누락 | int8 정밀도에서 특정 발화 구간이 통째로 사라짐 | VAD(무음 감지)가 저정밀도 연산에서 해당 구간을 무음으로 오판 | float32로 정밀도 상향하여 해결 |
| JSON 파싱 실패 | 요약 결과가 `{"error": "Json 해석 실패"}`로 반환됨 | LLM 응답에 `"null"`(문자열)이 섞이거나, 중첩 JSON에서 첫 `}`만 잘라내는 파싱 버그 | 정규식으로 `"null"` → `null` 치환, 마지막 `}`까지 포함하도록 파싱 로직 수정 |
| 컨텍스트 초과 | `Requested tokens exceed context window` 오류 | 긴 회의의 전사 원문이 모델의 최대 처리 길이를 초과 | `n_ctx` 확장(8192→32768) + 정리본 생성 단계만 예외 처리하여 실패해도 전체 파이프라인은 계속 진행되도록 격리 |
| 중복 업로드 미인식 | 같은 파일을 여러 번 업로드해도 매번 새로 처리됨 | 파일명만으로는 동일 파일 여부를 판단할 수 없음 | 파일 내용 기반 SHA-256 해시를 계산해 중복 여부 판단 |

## 5. 알려진 제약 사항
 
- 매우 긴 회의(수 시간 단위)는 정리본 생성 단계에서 컨텍스트 한도로 인해 생략될 수 있으며, 이 경우 전사·요약은 정상적으로 제공됩니다.
- 유사 발음, 저품질 녹음 구간에서는 전사 오류가 발생할 수 있으며 현재는 자동 교정 기능이 없습니다.
- 화자 분리(누가 말했는지 구분) 기능은 아직 구현되지 않았습니다.
